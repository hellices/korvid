# korvid v0.6.1

v0.6.1 is a security and packaging update to v0.6.0. It changes no feature:
everything in the
[v0.6.0 release notes](https://hellices.github.io/korvid/release-notes/v0.6.0/)
still applies.

## Why upgrade

v0.6.0 was packaged with runtime dependencies that now have published
advisories, one of them critical. The Homebrew formula installs exactly the
versions a release was tested with, and the `[agent]` extra pins LiteLLM
exactly, so neither moves until korvid is released again.

## Security fixes

| Package | v0.6.1 ships | Advisories fixed |
| --- | --- | --- |
| `certifi` | 2026.10.19 | critical: the CA bundle trusted emSign roots whose intermediate keys were compromised |
| `aiohttp` | 3.14.4 | three high (unbounded memory and CPU use, no initial header timeout in the server, multipart file descriptor exhaustion) and five lower |
| `filelock` | 4.2.4 | high (a planted symlink or journal file redirects `ReadWriteLock`), and two low ones on Windows |
| `litellm` | 1.100.4 | high: CVE-2026-114612, privilege escalation in the LiteLLM proxy |
| `opentelemetry-api` | 1.45.1 | moderate: unbounded `tracestate` parsing |

- **certifi matters most.** The agent's HTTPS connections to model providers
  trust its CA bundle.
- **aiohttp** is the HTTP stack of korvid's Kubernetes client.
- **The LiteLLM advisory** is in LiteLLM's proxy server, which korvid never
  runs or imports, so korvid was not exploitable through it. The update stops
  dependency scanners from flagging it.

The development tooling also moves to patched GitPython and virtualenv
versions, which do not ship with korvid.

## Reliability fixes

- Quitting right after approving a Deployment scale or restart no longer fails
  while the operation result screen opens.
- Quitting right after interrupting an agent turn no longer fails when the
  turn settles during shutdown.
- On Intel macOS, the Homebrew formula uses a prebuilt Rust toolchain instead
  of building one from source.

The safety perimeter is unchanged. Agent investigation remains read-only.
Agent writes remain structured tools with no shell. The resolved policy arms
only exact registry tool names, import-time metadata validates dispatch, and
`ToolExecutor` rejects an unknown tool. It performs typed argument validation
before every dispatch. Every write opens an approval dialog, requires a fresh
approval keystroke, and revalidates the exact target UID. Results still pass
through masking, and audit logging remains fail-closed.

## Documentation

- [Practice on a throwaway cluster](https://hellices.github.io/korvid/getting-started/#practice-on-a-throwaway-cluster)
  walks through a disposable kind cluster with healthy and deliberately broken

## Kubernetes versions verified

Kubernetes 1.33, 1.34, 1.35 and 1.36, by the Kubernetes version matrix on
throwaway kind clusters.

## Install or upgrade

Install with `uv`:

```bash
uv tool install 'korvid[all]==0.6.1'
```

Reinstall the exact version with `uv` or `pipx` when upgrading:

```bash
uv tool install --force 'korvid[all]==0.6.1'
pipx install --force 'korvid[all]==0.6.1'
```

Homebrew users get v0.6.1 from `brew upgrade korvid` once the tap is updated.

## Verify

After the maintainer publishes the
[GitHub release](https://github.com/hellices/korvid/releases/tag/v0.6.1),
download its artifacts, verify both attestations, and check the wheel against
the checksum manifest:

```sh
set -eu
gh release download v0.6.1 --dir dist/v0.6.1 --repo hellices/korvid
gh attestation verify dist/v0.6.1/korvid-0.6.1-py3-none-any.whl --repo hellices/korvid
gh attestation verify dist/v0.6.1/SHA256SUMS --repo hellices/korvid
(cd dist/v0.6.1 && shasum --algorithm 256 --check SHA256SUMS)
uvx --from 'korvid[all]==0.6.1' korvid --version
```

The final command must report `korvid 0.6.1`.

## Known limits
