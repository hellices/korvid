# korvid v0.3.0 release

## Goal

Publish the compatible feature work merged since v0.2.0 as korvid v0.3.0.

## Version choice

Use a minor version because the release adds substantial operator-facing
functionality without intentionally breaking supported interfaces:

- graph-derived blast-radius previews;
- workload scale-down impact previews;
- pod resize impact previews;
- node maintenance impact previews;
- the README MCP follow demonstration;
- installation and release-policy improvements.

## Release preparation

Prepare a release branch from the latest `origin/main`. Update package metadata,
the project entry in `uv.lock`, current-version installation examples, security
support language, release documentation and release contracts from 0.2.0 to
0.3.0. Preserve the historical v0.2.0 release notes unchanged and add
`docs/release-notes/v0.3.0.md`.

The required cross-version gate upgrades a clean published
`korvid[all]==0.2.0` environment to the exact v0.3.0 candidate wheel produced by
the release dry run.

## Lockfile safety

The project version change must be reflected in `uv.lock`. Re-lock only with all
user configuration and package-index environment variables neutralized, as
specified in `docs/dev/quality-gates.md`. If direct PyPI access is unavailable,
use the repository Relock workflow rather than recording private mirror URLs.

## Validation

Before review:

1. run the release policy, release script, lockfile and README contracts;
2. run the full repository gate;
3. merge the release PR through the normal human-maintained path;
4. run the non-publishing Release workflow dry run on the merged `main`;
5. run the documented v0.2.0-to-v0.3.0 candidate upgrade gate.

## Publication boundary

Do not create or push a tag before the release PR is merged and the exact-main
dry run and upgrade gate pass. Publication begins only when a maintainer creates
and pushes the annotated `v0.3.0` tag for the reviewed `origin/main` commit.
The tag workflow performs build, smoke matrix, SBOM, offline bundle,
attestation, PyPI publication and GitHub Release finalization. Verify the
published artifacts and Homebrew update using the release runbook.
