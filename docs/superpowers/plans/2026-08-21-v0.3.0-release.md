# korvid v0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare, review, dry-run, publish and verify korvid v0.3.0 from the exact reviewed `main` commit.

**Architecture:** A reversible release-preparation PR updates every current-version contract and adds release notes. Publication remains a separate maintainer-controlled phase: merge the PR, run the exact-main dry run and v0.2.0 upgrade gate, then push one annotated v0.3.0 tag to activate the existing fail-closed release workflow.

**Tech Stack:** Python packaging (`pyproject.toml`, uv lockfile), pytest release contracts, GitHub Actions, PyPI Trusted Publishing, GitHub attestations, Homebrew tap automation.

## Global Constraints

- Target version is exactly `0.3.0`; tag is exactly `v0.3.0`.
- Preserve `docs/release-notes/v0.2.0.md` as historical documentation.
- The cross-version gate upgrades published `korvid[all]==0.2.0` to the exact dry-run v0.3.0 wheel.
- Do not create or push the tag before the release PR is human-merged and the exact-main dry run and upgrade gate pass.
- Never re-lock behind a package mirror. Neutralize uv config and all package-index environment variables.
- Do not merge the release PR automatically.
- Never delete, move or reuse a published tag/version during recovery.
